# Results — Trained on the Real MIT-BIH Arrhythmia Database

These are actual results from running the full pipeline against all 48 real
MIT-BIH records (not synthetic/demo data). Generated by:

```bash
python src/preprocessing/build_dataset.py     # data/mitdb/ populated with real PhysioNet records
python src/models/train_baseline.py --model rf
python src/models/train_baseline.py --model svm
python src/models/train_cnn.py --epochs 7
python src/models/evaluate.py --model all
```

## Dataset

- **48/48 real MIT-BIH records** processed (100–124, 200–234)
- **109,451 total annotated beats**: 90,593 Normal, 18,858 Arrhythmic
- 80/20 train/test split (stratified, random_state=42), **21,891 beats** in the held-out test set (18,119 Normal, 3,772 Arrhythmic)
- Split is random at the beat level, not patient-level — a solid baseline evaluation, but not the inter-patient split used in some published benchmarks. For a stricter evaluation, split `record_ids.npy` by patient before train/test.

## Model comparison

| Model | Trained on | Accuracy | Precision | Recall | F1-score |
|---|---|---|---|---|---|
| Random Forest | Full 87,560 training beats | 97.82% | 95.72% | 91.41% | 93.52% |
| SVM (RBF kernel) | 15,000-beat stratified subsample* | 89.76% | 67.05% | 79.80% | 72.87% |
| **1D CNN** | Full 87,560 training beats, 7 epochs | **98.01%** | 94.11% | **94.38%** | **94.24%** |

\* RBF-kernel SVMs scale poorly (~O(n²)–O(n³)) past roughly 15–20K samples, so SVM was trained on a stratified subsample of the training set while RF and CNN trained on the full set. The test set (21,891 beats) is identical and full-size across all three models — this is a fair like-for-like evaluation, just an unequal training budget for SVM, which is standard practice for kernel SVMs at this scale.

## Interpretation

- The 1D CNN outperforms both handcrafted-feature baselines, consistent with the
  literature cited in the project synopsis (§4) — raw-waveform deep learning
  models often beat handcrafted RR-interval/QRS-duration features.
- Random Forest is a strong, cheap baseline — within ~1 point of the CNN on
  accuracy and F1, and faster to train.
- SVM underperforms here mainly due to the reduced training sample, not an
  inherent weakness of the approach — with the full training set (impractical
  at this kernel/scale without approximation techniques like the Nyström
  method or a linear kernel), it would likely close some of the gap.
- The CNN was trained for only 7 epochs due to time constraints; training
  curves were still improving, so a longer run (with the early stopping already
  configured in `train_cnn.py`) would likely improve results further.

## Files in this package

- `results/models/` — trained model weights (`rf.joblib`, `svm.joblib`, `cnn_model.keras`) and their scalers/test splits
- `results/figures/` — confusion matrix plots for all three models
- `data/processed/` — extracted features and labels from the real dataset (`features.npy`, `labels.npy`, `record_ids.npy`). Raw waveform segments (`segments.npy`) were excluded from this package due to size (~226 MB) — regenerate with `build_dataset.py` against `data/mitdb/` if needed for retraining the CNN.
